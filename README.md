# ครัวสุขภาพ – 3 มื้อใน 1 วัน (ต้นแบบ)

เกมเว็บ 2D ด้วย HTML + CSS + JavaScript + **Phaser 3** สอนการเลือกอาหารสำหรับเด็กที่เป็นโรคไต
(3 ด่านตามมื้ออาหาร: อาหารเช้า → อาหารกลางวัน → อาหารเย็น แล้วจบด้วยหน้าสรุปทั้งวัน)

## วิธีเปิดด้วย VS Code + Live Server
1. เปิดโฟลเดอร์ `kidney-kitchen` ใน VS Code (File > Open Folder)
2. ติดตั้งส่วนขยาย **Live Server** (Ritwick Dey) จากแท็บ Extensions
3. คลิกขวาที่ `index.html` > **Open with Live Server** (หรือกด "Go Live" มุมล่างขวา)
4. เบราว์เซอร์จะเปิดที่ `http://127.0.0.1:5500` ต้องต่ออินเทอร์เน็ตเพื่อโหลด Phaser และฟอนต์จาก CDN

## วิธีเล่น (มุมมองด้านบน เดินได้ 4 ทิศ)
| ปุ่ม | หน้าที่ |
|---|---|
| A / D / W / S หรือ ลูกศร | เดิน ซ้าย / ขวา / ขึ้น / ลง |
| E | เก็บวัตถุดิบ (ต้องยืนใกล้) / จัดอาหารที่จานสีเขียว (ต้องยืนใกล้) |
| F | ดูข้อมูลโภชนาการของวัตถุดิบที่อยู่ใกล้ |
| Esc | ปิดหน้าต่าง (ยกเว้นหน้าสรุป) |

**บนมือถือ:** ใช้จอยสติ๊กด้านซ้ายเพื่อเดิน และปุ่ม E / F ด้านขวาเพื่อเก็บ/จัดอาหารและดูข้อมูล (แสดงอัตโนมัติบนจอสัมผัส) แนะนำให้เล่นแนวนอน ตัวเกมจะขยายเต็มพื้นที่หน้าจออัตโนมัติเมื่อเปิดลิงก์ ไม่ต้องกดปุ่มขยายจอก่อน ปุ่ม ⛶ เป็นตัวเลือกสำหรับเข้า/ออกจาก Fullscreen ของเบราว์เซอร์
ทดสอบมือถือผ่าน Live Server: ต่อมือถือกับคอมเครื่องเดียวกันใน Wi-Fi เดียวกัน แล้วเปิด `http://<IP ของคอม>:5500`

เก็บวัตถุดิบ → ดูข้อมูล → เดินไปจานสีเขียว → เลือกให้ครบ 3 อย่าง → ยืนยัน → ดูสรุปผลรวมสารอาหาร → ไปด่านถัดไป (กลางวัน → เย็น) → สรุปทั้งวัน → เล่นใหม่ทั้งวัน
แถบเก็บวัตถุดิบเป็น Hotbar ช่องเล็กแบบ Minecraft อยู่กลางล่างจอ ตัวเกมจะขยายเต็มพื้นที่หน้าจอโดยอัตโนมัติทั้งมือถือและคอมพิวเตอร์ โดยไม่ยืดภาพ: UI ยึดขอบจอและขยายตัวอักษรตามสัดส่วนเท่ากันทั้งสองแกน ส่วนพื้นหลังห้องวาดต่อออกไปให้เต็มจอทุกสัดส่วน และมีปุ่ม ⛶ สำหรับเข้า/ออกจาก Fullscreen ของเบราว์เซอร์ ขณะเปิดหน้าต่างใดๆ ตัวละครจะหยุดเดินและเก็บของไม่ได้

## ภาพและเสียง
- ฉากเป็นห้องครัววาดด้วยโค้ด แยกเป็น 3 ฟังก์ชันตามมื้อ: `drawBreakfastRoom()` `drawLunchRoom()` `drawDinnerRoom()` (สองมื้อหลังใช้ตัววาดโครงห้องร่วมกันคือ `drawBigKitchen(palette, opt)` แต่คนละชุดสี คนละแสง) ไอคอนอาหารวาดด้วย Canvas (`ICON_DRAW`) ใช้ทั้งในฉากและหน้าต่าง UI ไม่ต้องมีไฟล์รูป
- เสียงและเพลงพื้นหลังสังเคราะห์ด้วย WebAudio (`SFX`) ไม่ต้องมีไฟล์เสียง เริ่มเล่นหลังแตะ/กดครั้งแรก ปุ่ม 🔊 บนแถบภารกิจใช้เปิด/ปิดเสียง (จำค่าไว้ในเครื่อง)
- ลูกเล่น: ประกายและข้อความลอยตอนเก็บของ วัตถุดิบลอยเบา ๆ ไฮไลต์ตัวที่อยู่ใกล้ ฝุ่นตอนเดิน ช่องเก็บของเด้งตอนได้ของ กระดาษสีเมื่อผลสรุปดี
- ลูกเล่นฉาก: เปลี่ยนด่านด้วยการเฟดสีของมื้อใหม่ + ป้ายบอกเวลา (07:30 / 12:00 / 18:30) + เสียงเปลี่ยนด่าน · ท้องฟ้านอกหน้าต่างและนาฬิกาเปลี่ยนตามมื้อ · ควันจากหม้อ · ฝุ่นลอยในลำแสงแดด · ตอนกลางคืนมีดาวกะพริบ แสงจันทร์ แสงโคมไฟแขวน แสงเตา/ตู้เย็นกะพริบเบา ๆ เงาใต้เคาน์เตอร์ ขอบภาพมืดอ่อน ๆ และแสงอุ่นใต้วัตถุดิบ (ไม่ใช้ overlay ดำทึบ)
- ระบบแสงใช้ภาพเรืองแสงนุ่ม ๆ แบบ additive blend (`makeLightTextures` / `addGlow` / `addBeam`) แทน Light2D ของ Phaser เพื่อให้ไอคอนอาหารไม่ถูกบดบังและทำงานเบาบนมือถือ
- ถ้าอยากใช้รูปภาพเอง ใส่ไฟล์เป็น texture ชื่อ `food_<id>` แทน `addCanvas` ใน `preload()`

## โครงสร้างโค้ด (`game.js`)
- `FOOD_DB` ฐานข้อมูลวัตถุดิบเดียว ใช้ร่วมกันทั้งหน้าข้อมูล หน้าจัดจาน และหน้าสรุป
- `MEAL_POOL` รายชื่อวัตถุดิบที่สุ่มได้ของแต่ละมื้อ · `SPAWN_RULES` / `mealCheck()` / `levelCombos()` / `pickIngredientsChecked()` / `auditMeals()` ระบบสุ่มแบบมีเงื่อนไข (ดูหัวข้อด้านล่าง) · `LEVELS` นิยามด่านทั้ง 3 (ชื่อ ภารกิจ จำนวนที่ต้องเลือก จำนวนที่สุ่มวาง ฯลฯ) · `addFood()` เพิ่มวัตถุดิบใหม่ + `ICON_DRAW` วาดไอคอน
- `sumNutrients()` คำนวณผลรวมจากวัตถุดิบที่เลือกจริง และจะ error หากปริมาณอ้างอิงไม่ตรงกัน
- บล็อก `ROOMS` (`/*ROOMS-BEGIN*/ … /*ROOMS-END*/`) เก็บข้อมูลผังของ "แต่ละด่านแยกกัน": `counterSlots` (ตำแหน่งวางวัตถุดิบ) `surfaces` (พื้นผิวเคาน์เตอร์ที่วางได้) `obstacles` (เฟอร์นิเจอร์ที่ตัวละครเดินทะลุไม่ได้) `bounds` `start` · ด่านเช้า = `BREAKFAST_SLOTS` (8 จุดเรียงแถวเดิม) · ด่านกลางวัน = `LUNCH_SLOTS` (11 จุด) · ด่านเย็น = `DINNER_SLOTS` (12 จุด) · `CFG` ปรับความเร็วและระยะเก็บ/โต้ตอบ
- `validateLevelLayout()` ตรวจผังทุกด่านตอนโหลดเกม (เตือนใน Console ถ้ามีช่องที่ไม่อยู่บนเคาน์เตอร์ ซ้อนกัน หรือเดินไปเก็บไม่ถึง) · `pickSlots()` สุ่มช่องวาง ถ้าด่านตั้ง `spreadZones: true` จะมีของอย่างน้อย 1 ชิ้นในทุกเคาน์เตอร์ (หลัง/ซ้าย/ขวา/กลางห้อง) · `resetWorld()` ทำการเปลี่ยนฉาก (ล้างห้องเก่า → วาดห้องใหม่ → วางวัตถุดิบ) โดยไม่แตะระบบเก็บ/จัดจาน/คำนวณสารอาหาร
- เปลี่ยน Emoji เป็นรูปภาพ: ใส่ path ที่ `sprite` ของวัตถุดิบ เช่น `sprite: 'assets/rice.png'`

## ระบบประเมินและแจ้งเตือน
- แต่ละวัตถุดิบมี "ปริมาณที่กินจริง" (เช่น ไข่ 1 ฟอง = 50 g) คำนวณ = ค่าต่อ 100 g × กรัมที่กิน ÷ 100 แล้วบวกกันเฉพาะ 3 อย่างที่เลือก
- เกณฑ์ต่อมื้อ = เกณฑ์ต่อวัน × 25% (แก้ที่ `PROFILE` ใน `game.js`) โซเดียม/โพแทสเซียม/ฟอสฟอรัสเป็น "ห้ามเกิน" ส่วนพลังงาน/โปรตีนเป็น "ช่วงที่เหมาะสม"
- ไฟจราจร: เขียว ≤ 70% ของเกณฑ์ · เหลือง 70–100% (หรือ ต่ำกว่าช่วง) · แดง เกินเกณฑ์
- จุดที่เตือน: (1) ตาราง % ในหน้าข้อมูลวัตถุดิบ (2) มาตรวัดสดในหน้าต่างจัดจาน + ข้อความป๊อปอัปเมื่อใส่แล้วเกิน (3) หน้าต่างถามซ้ำก่อนยืนยันถ้า "ยังไม่เหมาะ" (4) หน้าสรุปแสดงตารางคำนวณ คำตัดสิน และคำแนะนำสลับวัตถุดิบ

## ข้อสำคัญเรื่องข้อมูลโภชนาการ
ค่าโภชนาการ ปริมาณที่กิน และ **เกณฑ์เตือนทั้งหมด** เป็น **ข้อมูลตัวอย่างสำหรับทดสอบระบบ** ยังไม่ผ่านการตรวจสอบกับแหล่งข้อมูลทางการ
และ **ไม่ใช่คำแนะนำทางการแพทย์** ก่อนใช้งานจริงควรแทนที่ด้วยค่าจากฐานข้อมูลที่เชื่อถือได้ (เช่น ตารางแสดงคุณค่าทางโภชนาการไทย) และให้แพทย์/นักกำหนดอาหารตรวจสอบ
แล้วเปลี่ยน `verified: true`

## ด่านและการสุ่มวัตถุดิบ
- **ฉากแต่ละด่าน:** ด่าน 1 = ครัวเล็กยามเช้า เคาน์เตอร์แถวเดียวด้านบน แสงแดดอุ่น · ด่าน 2 = ครัวใหญ่ตอนกลางวัน มีตู้เย็น อ่างล้างจาน เตา+เครื่องดูดควัน ตู้เก็บของ เคาน์เตอร์ซ้าย/ขวา และเกาะกลางห้อง ต้องเดินสำรวจหาวัตถุดิบ · ด่าน 3 = ครัวผังเดียวกับด่าน 2 แต่เป็นกลางคืน (คนละชุดช่องวางของ)
- **ด่าน 1 อาหารเช้า** (แนะนำระบบ) · **ด่าน 2 อาหารกลางวัน** (วัตถุดิบหลากหลายขึ้น มีตัวเลือกให้เปรียบเทียบ เช่น ข้าวสวย/ข้าวกล้อง, บะหมี่กึ่งสำเร็จรูป/เส้นเล็ก) · **ด่าน 3 อาหารเย็น** (ปิดคำใบ้ตรง ๆ: ไม่แสดงคำแนะนำสลับวัตถุดิบ และไม่เด้งเตือนว่าอะไรทำให้เกินตอนใส่จาน ผู้เล่นต้องดูมาตรวัดแล้วตัดสินใจเอง) จบแล้วแสดงสรุปทั้งวัน
- ทุกครั้งที่เริ่มด่าน ระบบสุ่ม `spawnCount` ชิ้น จาก `MEAL_POOL` ของมื้อนั้น (ไม่ซ้ำ) สุ่มเฉพาะรายการที่ผ่าน `hasFullData()` คือมีค่าโภชนาการครบทุกตัว ปริมาณที่กิน และปริมาณอ้างอิงถูกต้อง รายการที่ข้อมูลไม่ครบจะถูกข้ามและแจ้งใน Console
- ให้มีกลุ่มอาหาร (`cat`: staple/protein/veg/fruit/drink/soup) อย่างน้อย `minCats` กลุ่มในแต่ละรอบ เพื่อให้จัดจานได้หลากหลาย (ไม่ใช่เกณฑ์ตัดสินผล)

### สุ่มแบบมีเงื่อนไข (Constraint-based Randomization) — หัวข้อ 1.6 ใน `game.js`
1. **ตรวจชุดอาหารล่วงหน้า (ขั้นที่ 1: ฐานข้อมูล)** `levelCombos(L)` คำนวณทุกชุด 3 อย่างที่ไม่ซ้ำจาก `MEAL_POOL` ของด่าน ด้วย `portionAmount()` + `ruleBounds()` ตัวเดิม (`mealCheck()`) แล้วแยกเป็น ผ่าน / ผ่านเต็ม / ไม่ผ่าน (พร้อมเหตุผล)
2. **สร้างแกน** `buildSeed()` สุ่มชุดที่ผ่าน 3 ชุดที่ต่างกัน (ซ้ำกันคู่ใดไม่เกิน `SPAWN_RULES.maxOverlap` อย่าง และไม่มีวัตถุดิบตัวเดียวอยู่ครบทั้ง 3 ชุด) อย่างน้อย 1 ชุดเป็นชุดผ่านเต็ม
3. **เติมตัวเลือก/ตัวหลอก** สุ่มวัตถุดิบอื่นเติมจนครบ `spawnCount` (เติมอย่างเดียว ไม่เอาออก ชุดผ่านเดิมจึงไม่หาย) พยายามให้ได้ `minCats` กลุ่ม
4. **ตรวจซ้ำกับของที่จะวางจริง (ขั้นที่ 2: วัตถุดิบในฉาก)** `analyzeSet()` นับชุดที่ผ่านจากวัตถุดิบที่สุ่มได้จริงอีกรอบ ต้อง ≥ `SPAWN_RULES.minPass` (3) ก่อนวางฉาก
5. **กันลูป/Fallback** สุ่มได้สูงสุด `SPAWN_RULES.attempts` ครั้งต่อขั้น แล้วผ่อนเงื่อนไขทีละขั้น: กลุ่มอาหาร → ชุดผ่านเต็ม → ความแตกต่างของ 3 ชุด (ยังต้องมีชุดผ่าน ≥ 3) ถ้ายังไม่ได้ ใช้การสุ่มแบบเดิมและ `console.error` ว่ารอบนั้นไม่ผ่านการตรวจ (ไม่ประกาศว่าผ่าน และ **ไม่ปรับตัวเลขโภชนาการ/เกณฑ์ให้เอง**)
- **นิยาม "ชุดที่ผ่าน"** = ไม่มีสารอาหารใดที่ `evaluateMeal` ตัดเป็นเกินเกณฑ์ (โซเดียม/โพแทสเซียม/ฟอสฟอรัส ห้ามเกิน · พลังงาน/โปรตีนห้ามเกินช่วงสูงสุด) และพลังงาน/โปรตีนไม่ต่ำกว่าช่วง · **ผ่านเต็ม** = ผ่าน และแร่ธาตุทุกตัวไม่เกิน 70% (`warnAt`) = `evaluateMeal` ให้ `good`
- **สารอาหารที่มีเกณฑ์ใน `PROFILE`:** พลังงาน, โปรตีน (ช่วง) · โซเดียม, โพแทสเซียม, ฟอสฟอรัส (ห้ามเกิน) · **ไม่มีเกณฑ์ผ่าน/ไม่ผ่าน:** คาร์โบไฮเดรต, ไขมัน (แสดงค่าอย่างเดียว ไม่นำมาตัดสิน)
- ผู้เล่นไม่เห็นว่าชุดไหนคือแกนที่เตรียมไว้ จัดจานและสรุปผลคำนวณจากสิ่งที่ผู้เล่นเลือกจริงใน `evaluateMeal` เท่านั้น

### ทดสอบผ่าน Console
- เปิดเกมแล้วดู Console: ตอนโหลดจะมีตาราง "ตรวจชุดอาหารล่วงหน้า" ของทั้ง 3 ด่าน และทุกครั้งที่เริ่มด่านมีบรรทัดผลตรวจของวัตถุดิบที่สุ่มวางจริง (✓ ผ่าน / ⚠ ผ่านแต่ผ่อนเงื่อนไข / ✗ ไม่ผ่าน)
- เติม `?debug=meals` ต่อท้าย URL เพื่อดูรายละเอียด: ตัวอย่างชุดที่ผ่าน ผลรวมสารอาหาร และเหตุผลที่ชุดอื่นไม่ผ่าน
- เรียกเองได้: `auditMeals({ verbose: true })` ตรวจฐานข้อมูลทุกด่าน · `auditSpawn(2000)` จำลองสุ่มซ้ำ 2,000 รอบต่อด่านและสรุปว่ามีรอบไหนไม่ผ่านหรือต้องผ่อนเงื่อนไขบ้าง
- ถ้าแก้ `FOOD_DB`/`MEAL_POOL`/`PROFILE` ในอนาคต (เช่น เมื่อได้ข้อมูลที่ตรวจสอบแล้ว) ให้เรียก `auditMeals()` อีกครั้ง ถ้าด่านใดมีชุดผ่าน < 3 จะขึ้น error ชัดเจน
- หน้าสรุปทั้งวันรวมค่าจากวัตถุดิบที่เลือกจริง 3 มื้อ เทียบกับ เกณฑ์ต่อมื้อ × 3 ด้วยตรรกะเดียวกับรายมื้อ
- **ค่าที่ยังไม่ได้ตกลงและตั้งไว้ชั่วคราว:** `pickCount` (3) `spawnCount` (8) `minCats` และ `hints` ของแต่ละด่านใน `LEVELS` · วัตถุดิบใหม่ทั้งหมดเป็นข้อมูลตัวอย่างสำหรับทดสอบ (`verified: false`) รอข้อมูลโภชนาการฉบับตรวจสอบแล้ว
